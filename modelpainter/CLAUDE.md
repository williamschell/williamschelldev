# CLAUDE.md — Splotchle 3D (working name)

A browser-based 3D texture painter that lives on williamschell.dev, built for one specific art style:
**painted cel shading**. Every object is painted twice — once **fully lit**, once **fully in shadow** —
plus an optional **edge** map. A toon shader blends between the two passes based on lighting, so the
painted look survives dynamic lighting in a 3D shooter.

The painter must feel like Splotchle (the existing 2D daily-blob drawing app on this site): same brush
feel, same pen pressure handling, same quick, playful UX.

---

## 0. Project facts

- Splotchle source location: `../splotchle/` (a sibling folder in the williamschell.dev repo)
- Splotchle stack: vanilla JS with native ES modules, no build step, vendored dependencies
- Splotchle brush engine entry point: `splotchle/js/draw.js` (`drawPoint`, `drawEnd`, `applyStyle`) and `splotchle/js/brushes.js` (`hairsFor`, `strokePaint`, `MARKER_ALPHA`)
- How the site is deployed: GitHub Pages, serving the repo as is. Nothing here can need a build.
- Where this app lives: `modelpainter/`, at williamschell.dev/modelpainter/

**Rule for Claude:** before writing any brush code, read Splotchle's brush engine and reuse it.
Do not write a new brush engine from scratch. If it's tightly coupled to Splotchle's canvas, extract it
into a shared module both apps import, without changing Splotchle's behavior.

**Running it:** from the repo root run `python -m http.server 8123` and open
`http://localhost:8123/modelpainter/`. ES modules don't load from `file://`.

**Testing it:** `tests/index.html` runs the unit tests in the browser. `tests/e2e.mjs` drives the real
app in Chrome with real input and checks actual texture pixels. Its header explains how to run it.

**Vendored files** (`vendor/`, license alongside each): three 0.187.0 (build plus the GLTF and OBJ
loaders), three-mesh-bvh 0.9.18, xatlasjs 0.2.0, comlink 4.4.2, fflate 0.8.3. The import map in
`index.html` and `tests/index.html` resolves the bare `three` imports.

## 1. Tech stack

- Match the site's existing conventions (see section 0). If none apply: **TypeScript + Vite**.
- **Three.js** for rendering, glTF/GLB/OBJ loading, and GLB export. Custom shaders via `ShaderMaterial`
  / `RawShaderMaterial` in GLSL (WebGL2).
- **three-mesh-bvh** for fast raycasting (cursor → surface hit, camera pivot, fill-by-click).
- **xatlas compiled to WASM** for automatic UV unwrapping (check npm for a maintained wrapper such as

## 2. Core concept: projects and passes

Each 3D object you work on is a **project**. A project contains:

| Item | Description |
|---|---|
| Mesh | The imported model (one texture set per project in v1; multi-material meshes are merged onto one atlas when unwrapped) |
| UVs | Original UVs from the file, or generated by the unwrapper |
| **Lit pass** | RGBA texture: how the object looks fully lit |
| **Shadow pass** | RGBA texture: how the object looks fully in shadow |
| **Edge pass** | Grayscale texture, default 50% gray. Shifts where the light/shadow boundary falls. Lighter = stays lit longer, darker = falls into shadow sooner. Painting it with textured strokes makes the shadow edge brushy. |
| Palette | Saved swatches for this project |
| Shader settings | threshold, softness, edge strength, rim color/power/strength, preview light |
| Undo history | In memory only (not saved) |

The UI always has one **active pass** (Lit / Shadow / Edge), switched with tabs and hotkeys `1` `2` `3`.

### Preview modes (hotkey `V` cycles)
- **Toon** (default): final shader with a draggable preview light.
- **Lit only**: shows the lit pass unlit, as a flat texture.
- **Shadow only**: shows the shadow pass unlit, as a flat texture.
- **Auto**: shows the pass you're painting while the brush is down and toon preview when idle.

Preview light: drag with `L` + mouse to orbit the light around the model; button to toggle a slow auto-rotate.
Seeing the blend while painting is the main reason this tool exists, so keep the preview fast.

### Helpers
- **Generate shadow from lit**: copy the lit pass into the shadow pass with adjustable hue shift
  (default slightly toward blue/purple), saturation, and value drop. This is a single undoable step.
- **Copy lit → shadow** / **Copy shadow → lit**: plain copies.
- **Reset edge to gray**.

## 3. The toon shader (canonical reference)

This GLSL is the **source of truth**. The painter's preview and William's game engine must use the
same math. Keep a copy in `docs/toon-shader.md` with comments, and keep it in sync with the code.

```glsl
// inputs
uniform sampler2D uLit, uShadow, uEdge;
uniform float uThreshold;     // default 0.5
uniform float uSoftness;      // default 0.04 (half-width of the transition)
uniform float uEdgeStrength;  // default 0.35
uniform vec3  uRimColor;      // default vec3(0.6, 1.0, 0.85)
uniform float uRimPower;      // default 3.0
uniform float uRimStrength;   // default 0.0 (off) in painter, per-character in game

// per light: direction L (to light), color C, shadow attenuation A (1 = unshadowed)
float lightMask(vec3 N, vec3 L, float A, float edge) {
    float ndl = dot(N, L) * 0.5 + 0.5;                 // half-lambert, 0..1
    float t   = ndl * A + (edge - 0.5) * uEdgeStrength; // cast shadows go in BEFORE the step
    return smoothstep(uThreshold - uSoftness, uThreshold + uSoftness, t);
}

vec3 shade(vec2 uv, vec3 N, vec3 V /* to camera */) {
    vec3 lit    = texture(uLit, uv).rgb;
    vec3 shadow = texture(uShadow, uv).rgb;
    float edge  = texture(uEdge, uv).r;

    vec3 col = shadow;                              // shadow pass = ambient base
    // for each light i:
    //   float m = lightMask(N, L_i, A_i, edge);
    //   col += (lit - shadow) * m * C_i;           // C_i = 1 for a white key light
    float rim = pow(1.0 - max(dot(N, V), 0.0), uRimPower);
    col += uRimColor * rim * uRimStrength;
    return col;
}
```

Notes:
- With one white light of intensity 1, the result goes exactly from the shadow pass to the lit pass.
  That's the core promise: **what you paint is what you get**.
- Cast shadows from the level are multiplied in before the smoothstep, so they also get the brushy edge.
- No outlines (the style has no lineart).

## 4. Painting tools

All painting tools work in both the **3D viewport** and the **2D UV view**.

### Brushes (pressure-sensitive; reuse Splotchle's engine)
| Brush | Behavior |
|---|---|
| **Pencil** | Small, hard, slight grain texture, pressure mainly affects opacity |
| **Pen** | Hard round, smooth, pressure affects size, full opacity |
| **Marker** | Flat-ish tip, semi-transparent, **does not build up within a single stroke** (stroke-buffer max blending), builds up across strokes |
| **Paintbrush** | Textured bristle tip, pressure affects size and opacity, soft build-up. This brush makes the signature look, so tune it carefully. |
| **Eraser** | Uses any of the above tips. On the Edge pass, it erases back to 50% gray instead of transparent. |

All brushes have size, opacity, spacing, and a pressure curve. `[` / `]` change size, `Shift+[`/`]` change opacity.

**Strokes are composited through a stroke buffer**: dabs go into a temporary per-stroke buffer, which is
then composited onto the layer with the stroke's opacity on pointer up (and live while drawing).
That's how the marker avoids build-up and how stroke opacity works properly.

### Other tools
- **Fill bucket** (`G`), with modes:
  - *Island*: fills the whole UV island under the cursor.
  - *Connected color*: flood fill in texture space with tolerance, clipped to the island.
  - *Whole object*: fills the active pass.
  In 3D, the cursor raycast picks the triangle, and that gives the island.
- **Eyedropper** (`I`, or hold `Alt` with any brush): choose whether it samples the **active pass texel**
  (default) or the **final rendered pixel**.
- **Color picker**: HSV wheel + SV square, hex input, recent colors, opacity slider. Always visible in the side panel.
- **Palette grabber**: drop or paste a reference image (or use the current pass), and it extracts a
  palette of N colors (k-means in a worker, N = 4–16) into the project palette. Click a swatch to use it,
  right-click to remove, drag to reorder.
- **Swatches**: per-project palette plus a global palette shared by all projects.

## 5. Viewports

### 3D viewport (main)
Painting happens directly on the model. A brush cursor circle is drawn on the surface, oriented
to the surface normal.

**Camera controls**
| Input | Action |
|---|---|
| **Right mouse hold** | Free-fly: mouse look (pointer lock), `W A S D` to move, `Q`/`E` down/up, `Shift` faster, scroll while held changes fly speed |
| **Middle mouse drag** | Orbit around the **surface point under the cursor at press** (BVH raycast). If nothing is hit, orbit around the last pivot. Show a small pivot dot while orbiting. |
| `Shift` + middle drag | Pan |
| **Scroll** | Zoom toward the point under the cursor, with step size proportional to distance (feels the same at any scale) |
| `F` | Frame the model |
| `Ctrl+Z` / `Ctrl+Shift+Z` (`Ctrl+Y`) | Undo / redo |
| `Tab` | Toggle 3D ↔ UV view (also a split view option) |

- Disable the browser context menu on the canvas. Use Pointer Events + pointer capture.
- **Pen barrel buttons usually send right/middle clicks.** All bindings must be remappable in a
  settings panel, with an alternate scheme: `Space` + drag = orbit, `Space+Shift` = pan, `Space+Ctrl` = zoom.
- Touch: two-finger orbit, pinch zoom, three-finger pan.

### 2D UV view
- Shows the active pass as a flat texture with a UV wireframe overlay (toggle `W`).
- Pan with middle mouse or `Space` + drag, scroll to zoom toward the cursor, `F` to fit.
- Painting here uses the exact same brush engine directly on the texture canvas.
- Optional split view: 3D and UV side by side, updating live.

## 6. How 3D painting works (implementation rules)

Use **screen-space projection painting baked into UV space**. Do not stamp dabs directly in UV space
from a single hit point, because that breaks at UV seams and stretches on angled surfaces.

For each batch of dabs (per frame, not per dab, when possible):
1. **Depth prepass**: render the mesh's depth from the current camera into a render target.
2. **UV-space pass**: render the mesh into the active pass's render target with
   `gl_Position = vec4(uv * 2.0 - 1.0, 0, 1)`. For each fragment (= texel):
   - Project its world position into the current camera's screen space.
   - **Visibility**: compare against the depth prepass (with a small bias). Skip if hidden.
   - **Facing falloff**: fade out where `dot(normal, toCamera)` is low, so dabs don't smear across grazing surfaces.
   - Compute the brush falloff from the screen-space distance to each dab center, sample the brush tip
     texture in screen space, and accumulate into the **stroke buffer** (UV-space render target).
3. Composite the stroke buffer into the active pass (live preview + final commit on pointer up).
4. **Seam dilation**: after each committed stroke, dilate painted texels a few pixels (default 4–8)
   outward into empty UV space, so mipmapping doesn't show seams. Keep a precomputed UV island mask
   (rendered once per UV layout) to know what's empty space.

Dab spacing comes from the screen-space stroke path (like 2D), so the brush feels identical in both views.

Brush size is in **screen pixels** by default (like painting on a picture of the model). Option: world-space size.

### Texture resolution
Per project: 512 / 1024 / 2048 / 4096, default 2048. All three passes share one resolution.
Use float or 8-bit RGBA render targets; 8-bit with correct sRGB handling is fine for v1.
Be strict and consistent about color space: picker colors are sRGB, textures are stored sRGB,
the shader decodes to linear for lighting math and encodes for display.

### Undo
Tile-based: split each texture into 64×64 tiles. Before a stroke commits, snapshot only the tiles it
touches. Cap memory (e.g. 256 MB), dropping the oldest history first. Pass switches, fills, generate-shadow
and unwrap are all undoable steps.

## 7. UV unwrapping

- On import, if the model has usable UVs, **keep them** (default). Detect missing/overlapping UVs and suggest unwrapping.
- **Auto unwrap** button runs xatlas in a worker, with padding (default 8 px at chosen resolution) and a texel density option.
- **Re-unwrap without losing paint**: when UVs change on a painted project, transfer the paint by
  rendering the mesh in the new UV space and sampling the old textures at the old UVs (per pass).
  Show a warning that some detail may soften.
- v2 (not now): manual seam marking, island move/scale in the UV view.

## 8. Projects, saving, export

- **Autosave** to IndexedDB (debounced, and on tab hide). Project list screen with thumbnails.
- **Project file** `.splotch3d`: a zip containing `project.json`, `mesh.glb`, `lit.png`, `shadow.png`,
  `edge.png`, palette. Save/load from disk.
- **Import**: `.glb`, `.gltf` (+ dropped resources), `.obj`.
- **Export GLB** for games:
  - `baseColorTexture` = **lit pass** (so other viewers show something sensible).
  - Custom extension in `extensionsUsed` (**not** `extensionsRequired`), name `WSCHELL_toon_paint`:
    ```json
    "extensions": {
      "WSCHELL_toon_paint": {
        "shadowTexture": { "index": 1 },
        "edgeTexture":   { "index": 2 },
        "threshold": 0.5, "softness": 0.04, "edgeStrength": 0.35,
        "rimColor": [0.6, 1.0, 0.85], "rimPower": 3.0, "rimStrength": 0.0
      }
    }
    ```
  - Document the extension schema in `docs/gltf-extension.md` so the game engine can parse it.
- **Export PNGs** of each pass separately.

## 10. Conventions and quality bar

- The painter must stay at 60 fps on a 2048 texture during a stroke on a mid-range laptop GPU.
  Batch dabs per frame; never read back GPU textures during a stroke.
- Keep the brush engine, the shader, and the UI in separate modules. The shader GLSL lives in its own
  files and is the same code documented in `docs/toon-shader.md`.
- Test models to keep in `test-assets/`: a cube with hard UV seams, a UV sphere, a low-poly character.
  Seams on the cube are the first thing to check after any painting change.
- Don't add accounts, servers, or sharing in v1.
- When something in this file conflicts with what's in the existing Splotchle code, ask William before changing either.

## 11. How this was built, and where it departs from the plan above

The plan had some tensions that were settled by judgment while William was away. These are the ones
worth a second look.

### The brush engine stays Splotchle's, so strokes aren't dabs
Sections 0 and 4 say to reuse Splotchle's engine. Section 6 describes GPU dab stamping. Splotchle's engine
doesn't stamp dabs: it strokes curves on a 2D canvas. The reuse rule was treated as the stronger one.

- A stroke draws on a 2D canvas using Splotchle's own `drawPoint` and `drawEnd`. That canvas is the stroke
  buffer. It's screen-space in 3D and texture-space in the UV view.
- Each frame, the changed rectangle is uploaded. In 3D, a UV-space pass then projects the canvas onto the
  texture with the visibility and facing tests from section 6. Everything else in section 6 is as written:
  depth prepass, composite, seam dilation.
- Splotchle changed by four added `export` keywords in `draw.js`. Its behavior is the same, and its tests pass.

What follows from that:
- **The camera can't move during a stroke**, since the projection assumes the view stays fixed.
- **Paint resolution depends on the stroke canvas.** It's 1.5 to 2 times screen resolution, so a stroke made
  zoomed far out and then inspected up close is softer than the texture could hold. Zoom in for fine detail.
- **Spacing** means the minimum distance between input points, as a share of brush size. Higher values give
  smoother, rounder lines rather than a visibly dotted stroke, since there are no dabs to space out.
- **The paintbrush draws its own bristle pieces.** It uses Splotchle's `hairsFor` and curve rule, but draws
  hairs furthest-ahead first with a small overlap, which removes a ladder artifact Splotchle's version has.
  It also adds a dry-brush falloff at light pressure. Splotchle itself doesn't have these improvements yet.

### Seam dilation is a lookup, not repeated blurring
Island padding is precomputed per UV layout as a map from each empty texel to its nearest island texel. So
dilating is one fullscreen pass, and it can run on every preview frame, so what you see while painting is
exactly what gets committed.

### Undo finds changed tiles by comparing
Every edit renders into a spare target. The GPU compares it with the current pass and halves the result down
to one flag per 64x64 tile, so only that tiny map gets read back. Stored tiles swap with the live ones on
undo and redo. All edits go through this one path, which is why fills and helpers are undoable for free.

### Known limits
- **Exports are static.** Import merges all meshes into one geometry, so rigs, skins and animations don't
  survive to the exported GLB. See `docs/gltf-extension.md` for the workaround. This matters for shooter
  characters and is the most likely thing to need v2 work.
- **Draco and Meshopt compressed files aren't supported.** The import error says to re-export uncompressed.
- **OBJ materials aren't read.** OBJ imports start as plain clay.
- **Not yet measured on real hardware:** the 60 fps target (section 10) and real tablet feel. The automated
  tests run on a software GPU with synthetic pen events.
- The working name "Splotchle 3D" and the `.splotch3d` extension come from this file. The folder is
  `modelpainter`. The site's homepage doesn't link here yet.
